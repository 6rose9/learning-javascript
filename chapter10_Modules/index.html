Module System

  1. ESM
  2. CommonJS
JavaScript engine
→ understands core JavaScript and ESM syntax (i.e., import / export).

→ V8/SpiderMonkey handle ESM parsing & execution

Browser
→ embeds a JavaScript engine (like V8 in Chrome, SpiderMonkey in Firefox).

→ provides runtime environment (including Web APIs), and the JS engine uses it while executing your code.

→ handles the things the engine can’t do on its own

  • Resolving module paths from URLs
  • Exposing document and window
  • Scheduling asynchronous tasks via the event loop

→ supports ESM natively

→ cannot use CommonJS directly; you need a bundler like Webpack or Vite.

Node.js
→ provides a JavaScript runtime environment (embeds V8).

→ supports both ESM and CommonJS modules.

→ provides extra APIs so JS code can do things a browser can’t do:

  • File System (fs)
  • Network (http, https, net, tls)
  • Path, URL, OS modules
  • Timers (setTimeout, setInterval)
  • Process & Environment
  • Module system

→ includes an event loop (from libuv library) to handle async operations: timers, I/O, network requests. V8 executes JS code, but the event loop orchestrates callbacks and asynchronous tasks.

→ does not have Web APIs like window, document, or fetch by default.
