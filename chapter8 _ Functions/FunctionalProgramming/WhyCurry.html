lexical (static) scoping

Scope is decided by where the function is written, not where it’s called.

JS already knows:
  1. The inner function’s parent scope is "add"
  2. x lives in that parent scope
  3. That relationship is locked in at creation time.
When the inner function runs, JS looks up variables like this:
  1. Local scope (inside the function)
  2. Outer lexical scope (closure)
  3. Next outer scope
  4. Global scope
This chain is called the scope chain.
So yes — the child can access parent variables, but only because:
The parent scope was captured earlier. Not because JS jumps back and executes the parent again
